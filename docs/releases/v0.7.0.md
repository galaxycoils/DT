# v0.7.0 — Rakazo layout and provider connections

Apple Silicon development preview. Install both applications from the DMG. This distribution uses an optimized release build and ad-hoc signatures; Developer ID signing, notarization, and full native certification remain outstanding.

## Interface

The native desktop and local browser companion use the palette and layout metrics from Rakazo commit `8aa0f787557697ee7fb5e2f16fb39f4249b35ad4`. `ui/design-tokens.json` generates both renderers' colors. Grok Muse branding remains.

- One conversation sidebar, remembered at 240–480 px or collapsed to 72 px. Bot counts no longer change the layout.
- Conversation previews, times, unread badges, vector avatars, centered conversation identity, rounded message bubbles, and a pill composer.
- Activity contains Feed, Goals, and Audit. Generated Spaces appear as **Pages**; their API identifiers remain compatible.
- Settings has a left navigation and a dedicated **Providers & models** page. Bot details remains resizable.
- System theme is the default for new configurations. Existing explicit themes remain selected.
- Measured transcript row heights prevent overlapping long messages. Browser drafts survive navigation and reload; storage failures are visible.

## Providers

Open **Settings → Providers & models**. Sign in or save a provider key, refresh the account's catalog, and select a model. Setup and model changes send a small, budgeted reply test. The first successfully verified provider becomes the workspace default. Existing bot and routine overrides retain precedence.

**Credentials saved**, **Authenticated**, **Models loaded**, and **Reply verified** describe different outcomes. A public catalog or a stored key does not mark a provider connected. A text reply test does not certify vision, tools, or media generation. API cost values remain estimates.

- ChatGPT uses Grok Muse's own public-client registration, a daemon-owned loopback callback, PKCE, nonce/state checks, and signed OIDC identity validation. The connection supports renewal, cancellation, account switching, and disconnect. Its catalog comes from the signed-in account. ChatGPT allowance is tracked separately from API spend.
- Meta, xAI, Kilo, OpenRouter, and custom/local OpenAI-compatible services share catalog discovery and selected-model verification. OpenAI API-key access is a separate choice from ChatGPT plan access.
- Kilo uses `https://ai-gateway.kilo.ai/api/v1`. Changed credential destinations require approval. xAI's language catalog supplies text model metadata.
- Nous Portal uses its documented device authorization protocol and refresh-token header. Inference destinations are restricted to the provider's paid and welcome resources.
- Provider changes apply to new requests without a daemon restart. Late sign-in or verification results cannot revive a disconnected or edited profile. Credential-store failures remain visible.

Cloud account access was unavailable during development validation. ChatGPT, Meta, xAI, Kilo, OpenRouter, Nous, and OpenAI API inference therefore require verification with the user's account. See [provider validation](../provider-validation.md) for the exact boundary between fixture coverage and live checks.

## Installation and verification

Download both release assets into one folder:

```sh
shasum -a 256 -c GrokMuse-0.7.0-macos-aarch64-adhoc.dmg.sha256
```

The release includes `GrokMuse.app` and `GrokMuseCUHelper.app`. Binary discovery prefers the running app and its sibling helper, preventing an older installed daemon from taking over a newly opened build.

Reproduce packaging from the `v0.7.0` tag with the pinned sibling Darius checkout:

```sh
cargo run --locked -p xtask -- dmg --release --identity - --output target/dist/GrokMuse-0.7.0-macos-aarch64-adhoc.dmg
cargo run --locked -p xtask -- verify-dmg --dmg-path target/dist/GrokMuse-0.7.0-macos-aarch64-adhoc.dmg
```

Full cross-platform acceptance, real account/checkpoint quality, clean-machine lifecycle evidence, and signed updater distribution remain governed by [release readiness](../release-readiness.md).
